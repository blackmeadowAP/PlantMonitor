# 07. Нейросеть и языковая модель

## Часть 1. Нейросеть-подсказчик (классификация болезней)

**Роль:** подсказка агроному (топ-3) и сортировка ленты. Не ставит диагноз, не влияет на статистику до решения агронома.

- Вход: closeup-фото; классы — по культуре поля: `healthy` + болезни культуры + `other`.
- Модель: лёгкий классификатор (YOLO-cls nano/small или EfficientNet-B0), вход 224 px (допустимо до 384), экспорт в ONNX.
- Файлы модели: `model.onnx`, `labels.txt` (одна метка на строку), `model_card.md` (версия, данные, метрики).
- Порог: `ML_CONFIDENCE_THRESHOLD` (0,6). Ниже — «ИИ не уверен».
- Метрики: полнота по классам болезней (главная), точность top-1, матрица ошибок. Новая версия выкатывается, только если лучше предыдущей на тестовых полях.

### Режимы (`ML_MODE`)

| Режим | Как работает |
| --- | --- |
| off | Подсказок нет (по умолчанию до шага 11) |
| local | `ml/local.py`: onnxruntime в процессе worker, CPU |
| space | `ml/client.py`: вызов Hugging Face Space через `gradio_client` (таймаут 120 с, 3 повтора — Space после простоя «просыпается») |

Общий интерфейс: `async def classify(image_bytes: bytes, crop_id: int) -> list[Prediction]` (Prediction: label, disease_id | None, prob).
Ошибка → лог + пропуск подсказки; разметка агронома не блокируется.

### Предобработка (одинакова при обучении и инференсе)
RGB → resize 224×224 → /255 → нормализация ImageNet (mean 0.485, 0.456, 0.406; std 0.229, 0.224, 0.225) → CHW → batch.

### Обучение (ml/train/)
1. Стартовая модель: открытые наборы (PlantVillage — лабораторные фото, PlantDoc — полевые, открытые наборы по пшенице). Учитывать: модель на лабораторных фото хуже работает в поле.
2. Дообучение: собственный экспорт (docs/05) при ~100–200 подтверждённых фото на класс; split по полям.
3. Где: бесплатные GPU-блокноты (Colab, Kaggle — проверить доступность) или ПК с видеокартой.
4. Скрипты: `export_dataset.py` → `train_cls.py` → `evaluate.py` (метрики в model_card.md) → `export_onnx.py`.

### Space (ml/space_app/app.py)
Gradio-интерфейс с функцией `predict(img) -> dict[label, prob]` (топ-3), `gr.Label(num_top_classes=3)`. Space приватный, бесплатное железо CPU Basic. Токен — `HF_TOKEN`.

## Часть 2. Языковая модель для текста отчётов

**Правило:** числа считает код; LLM только формулирует текст по фактам.

- Клиент: `openai` SDK с `base_url = LLM_URL` (Ollama: `http://ollama:11434/v1`). Смена модели — через `.env`.
- По умолчанию — локальная открытая модель 7–8B через Ollama (данные не покидают сервер). Внешний API — только с явного разрешения заказчика.
- `temperature = 0.2`; ответ — строго JSON `{"main": str, "actions": [str]}` (для шаблона Б — `{"summary": str, "attention": [str]}`).

### Системный промпт (reports/llm.py)
```text
Ты — помощник агронома-фитопатолога. Пиши по-русски, деловым стилем, кратко.
Используй ТОЛЬКО числа, названия полей, предприятий и болезней из блока ФАКТЫ. Не придумывай данных.
Если данных недостаточно — так и напиши. Не назначай препараты и дозы.
Отвечай только JSON указанного формата.
```

### Валидация ответа
1. JSON парсится и соответствует схеме (pydantic).
2. Все числа из текста (регулярное выражение для целых и десятичных, с запятой и точкой) присутствуют среди значений фактов (с округлением до 1 знака).
3. Все упомянутые «Поле №…» и названия предприятий — есть в фактах.
4. Провал → 1 повтор с сообщением об ошибке; повторный провал → резервный текст без LLM (шаблонные предложения по фактам).
5. Кэш: если `facts_hash` не изменился — использовать сохранённый `llm_summary`.

### Иерархия
Отчёт области = факты области + `llm_summary.main` каждого предприятия за период (как «заметки агрономов»).
Комментарии агрономов и работников передаются в блоке ЗАМЕТКИ (до 30 последних, каждый ≤ 300 символов).
