# AGENTS.md — правила для ИИ-агента

Этот файл читает любой ИИ-агент (Cline, Aider, Qwen Code, Claude Code, Codex и др.) перед работой.
Если ваш инструмент ищет другое имя файла (`CLAUDE.md`, `QWEN.md`, `.clinerules`), скопируйте этот файл под нужным именем.

## Проект в двух абзацах

Agro Monitor — система оперативного сбора данных о болезнях сельскохозяйственных культур в Беларуси.
Работники хозяйств ежедневно фотографируют контрольные точки полей и отправляют снимки в Telegram-бот.
Агроном предприятия размечает фото (здорово / подозрение / болезнь), выезжает на очаги и подтверждает их.
Суперпользователь (чиновник исполкома или специалист, отвечающий за предприятия и их урожайность)
видит карту области с предприятиями, динамику болезней и скачивает PDF-отчёты.

Принципы: никаких спутников и дорогого оборудования — только смартфон и Telegram; данные с поля
доходят до карты области в течение одного дня; система должна работать даже без ИИ-функций.

## Стек (не менять без согласования)

- Python 3.12; управление зависимостями — `pyproject.toml` + `uv` (или pip + requirements.txt, если uv недоступен).
- Telegram: aiogram 3.x, long polling, FSM-хранилище в Redis.
- API для Mini App: FastAPI + uvicorn.
- БД: PostgreSQL 16 + PostGIS; SQLAlchemy 2.x (async, asyncpg), Alembic, GeoAlchemy2.
- Очередь и расписание: Redis, arq (фоновые задачи), APScheduler (cron-задачи).
- Файлы: S3-совместимое хранилище через boto3 (локально — MinIO, в пилоте — Cloudflare R2); архив оригиналов — закрытый Telegram-канал.
- Изображения: Pillow, opencv-python-headless.
- Отчёты: Jinja2 + WeasyPrint (PDF), matplotlib (графики), staticmap (карта-картинка).
- Карта: чистый HTML/JS + Leaflet + OpenStreetMap, Telegram WebApp JS SDK. Без React и сборщиков.
- ML: onnxruntime (инференс); обучение — отдельные скрипты в `ml/` (PyTorch / Ultralytics), не входят в образ бота.
- LLM: openai-клиент к OpenAI-совместимому серверу (по умолчанию Ollama).
- Качество: ruff (линтер + форматтер), pytest + pytest-asyncio, testcontainers или отдельная тестовая БД в docker compose.
- Запуск: Docker Compose.

## Правила работы

1. **Один шаг за раз.** Выполняй только шаг из docs/08_ROADMAP.md, который назвал человек. Не реализуй функции следующих шагов «заранее».
2. **Сначала план, потом код.** Перед изменениями перечисли файлы, которые создашь или изменишь, и тесты. Если в документации пробел или противоречие — задай вопрос и жди ответа.
3. **Документация — источник правды.** Если код расходится с docs/, прав docs/. Если нужно изменить требование — сначала предложи правку docs/, код — после подтверждения.
4. **Тесты обязательны** для: расчёта показателей, генерации заданий, проверки геопозиции, прав доступа, проверки чисел в ИИ-резюме. Нельзя удалять или ослаблять тесты, чтобы они прошли.
5. **Перед завершением шага:** `ruff check . && ruff format --check . && pytest` — всё зелёное.
6. **Миграции:** только новые миграции Alembic; уже применённые не редактировать.
7. **Секреты:** только через переменные окружения (`core/config.py`, pydantic-settings). Никаких токенов в коде, тестах, логах, коммитах. `.env` в `.gitignore`.
8. **Права доступа** проверяются в сервисном слое, а не только в хэндлерах: агроном — только своё `org_id`, суперпользователь — только свой `region_id`, работник — только свои задания и фото.
9. **Отказоустойчивость:** недоступность S3, нейросети или LLM не должна ломать приём фото и разметку. Ошибки внешних сервисов — в лог + повтор через очередь.
10. **Тексты для пользователей** — на русском, короткие, с кнопками вместо ввода текста, где возможно. Тексты сообщений собраны в `bot/texts.py`.
11. **Время:** хранить в UTC (`timestamptz`), показывать в Europe/Minsk. Расписание задач — по Europe/Minsk.
12. **Координаты:** `geography(Point, 4326)`, порядок в PostGIS — (lon, lat). Расстояния — `ST_Distance` по geography (метры).
13. **Стиль кода:** типизация, небольшие функции, бизнес-логика в `core/services/`, хэндлеры бота тонкие. Комментарии и docstring — на русском.
14. **Отчёт в конце шага:** что сделано; как проверить руками (команды и действия в боте); что не сделано; предлагаемое сообщение коммита.

## Команды

```bash
docker compose up -d db redis minio        # инфраструктура
docker compose run --rm app alembic upgrade head
docker compose run --rm app python -m scripts.seed   # тестовые данные
docker compose up bot api worker            # приложение
docker compose run --rm app pytest
ruff check . && ruff format .
```

## Чего не делать

- Не подключать спутниковые данные, платные API карт, React/Vue, ORM кроме SQLAlchemy, другие фреймворки ботов.
- Не отправлять данные предприятий во внешние LLM без явного разрешения (по умолчанию LLM локальный).
- Не ставить окончательный диагноз нейросетью: ИИ только подсказывает, решает агроном.
- Не назначать в ИИ-тексте препараты и дозы.
